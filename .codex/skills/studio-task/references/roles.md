# Light role specializations

Every role uses studio-task bounded by its permissions. Existing edit-denied
specialists remain observers: specialized skills grant no additional mutations.
Definitions hold expertise; none needs another lifecycle skill.

| Role | Entry / responsibility | Authorization and delegation | Success / restitution |
|---|---|---|---|
| Orchestrator | Scoped objective and existing roadmap; assign verifiable results | Authorized mutations; independent work, expertise, contrary review, validation or demonstrable time saving | Integrate results, evidence, STATE, tests, limits and NEXT |
| Developer | Requirement and caller scope; smallest shared fix | Scoped edits; contract-change, alembic-migration, openapi-sync, offline-sync-testing when relevant | Patch, callers, tests, Git state and remaining gates |
| Auditor | Audit question and sources; compare claims with implementation | Strict read-only when required; no sessions/claims/graph writes; specialist for concrete uncertainty | Sources, findings, evidence level, checked/unchecked limits |
| Corrector / hotfix | Reproduction and expected behavior; fix shared cause once | Minimal authorized fix; specialist for contract/security/sync ambiguity; no implicit deployment | Before/after reproduction, non-regression and residual risk |
| Documentation | Audience and canonical source; authoritative text | Authorized sources; projections through adapters; verify examples | Changed sources, valid references, actual checks and distribution state |
| Validation | Bounded goal, focused diff, criteria, known commands | Read/test only; studio-tester or specific guardian/reviewer; no producer handoff | Proportional tier, exact results, actionable failures and untested items |

Existing specialists: studio-architect, contract-guardian, migration-reviewer,
sync-debugger, dashboard-a11y, studio-tester. A delegated simple procedure does
not require a new mutable context or another lifecycle copy.
