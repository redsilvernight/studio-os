# DEC-0093 — Desktop P1: local contracts `studio.local/v1`

Status: **accepted** (human validation 2026-09-20)
Date: 2026-09-20
Task: `[Desktop P1] Contrats locaux & architecture client`
Server decision UUID: `799cc332-8431-4438-9dbc-1d2045e6974d` (readable ID `DEC-0093`, status `accepted`)

## Context

DEC-0091 fixes Tauri 2 as a thin shell over a shared Dashboard, with a local
daemon and a Local Bridge. DEC-0092 makes `CodeGraphProvider` the canonical
boundary and Graphify an optional, separately installed adapter. P2-P10 lanes
need stable, typed contracts and shared fixtures before any implementation.

## Decision

P1 adds a contracts-only package `studio_contracts.local` (protocol
`studio.local/v1`), independent of Tauri, Graphify, Obsidian and any harness
vendor. No server contract changes; nothing in P2+ is implemented.

- **Handshake**: negotiation by protocol range plus capabilities, never by
  package version. Outcomes: compatible, compatible_degraded, daemon_too_old,
  desktop_too_old, capability_missing, protocol_incompatible. Any failure is
  fail-closed (`silent_fallback: false`).
- **Local Bridge**: closed, table-driven allowlist of typed commands and events
  with per-command capability, payload, response and deadline limits. No shell
  execution, arbitrary filesystem access, process spawn or generic HTTP proxy;
  a test guards forbidden primitive terms.
- **DaemonControl**: status, lifecycle, crash recovery and outbox replay. Outbox
  partitions are keyed by (origin, profile, machine); replay under a different
  identity is refused (`IDENTITY_MISMATCH`).
- **LocalWorkspaceConfig**: no secret values, only `SecretReference`.
- **Identities**: `HumanIdentity` and `MachineIdentity` are distinct types.
  Only `SecretReference`/`SecretReferenceStatus` cross the boundary; secret
  values are rejected by structural guards.
  Amendment (DEC-0130, proposed): `identity.enroll` carries the human session
  as the single write-only secret input (`IdentityEnrollRequest.human_session`).
- **KnowledgeProvider / CodeGraphProvider / HarnessAdapter**: provider-neutral
  contracts sharing one provider-state invariant. Markdown stays canonical, the
  index is derived, Obsidian is optional, Graphify is a non-canonical adapter
  identified only by an adapter id value.
- **Common graph schema**: sources knowledge/code/projection with mandatory
  provenance, per-source relation allowlists, a frontier for partial graphs and
  cross-source edges only through a projection source.
- **Publication policy**: everything is `LOCAL_ONLY`; only a
  `SharedStatusSummary` may be shared, never automatically, always after
  confirmation. Transport is not implemented (`TRANSPORT_UNAVAILABLE`).
- **Fixtures**: generated JSON schemas, valid/invalid fixtures and the bridge
  allowlist under `contracts/local/`, regenerated by
  `uv run python -m studio_contracts.local.export`; a drift test keeps them in
  sync with the Python builders.

## Consequences

- Lanes P2-P10 code against language-neutral schemas and fixtures.
- Any future breaking change of a `studio.local` model needs a protocol bump.
- The server JWT still maps to the dashboard machine; a distinct human/machine
  identity on the server side is deferred to a later, explicit contract change.
- Confinement of workspace roots relies on the implementation: any root
  transition (`current_roots` -> `config.roots`, including the first
  authorization) must carry a daemon-issued `root_confirmation_id` (native folder
  selection), enforced by the request contract; a stable config keeps none. P2+
  must issue the id and check `current_roots` against the stored config.
- Publishing shared summaries needs a server contract that P1 does not create.

## Human validation (2026-09-20)

- Accepted on substance; `studio.local/v1` is the common contract baseline for
  P2-P10. Compatible additive evolutions follow the versioning rules; no lane
  redefines the protocol or the P1 contracts unilaterally.
- Publication transport deferred: local data stays `LOCAL_ONLY`,
  `SharedStatusSummary` is the only explicitly shareable surface, never
  published automatically.
- Server-side human identity deferred; P1 guarantees the Human/Machine
  separation and fail-closed behaviour without a new server contract.
- `root_confirmation_id` is required on the root transition
  (`current_roots` -> `config.roots`), not on every `LocalWorkspaceConfig`.
- The server record body still reads PROPOSED (bodies are immutable); the
  server status is `accepted` and this file is canonical.

## Alternatives rejected

- Generic command channel in the bridge (shell/HTTP proxy): rejected, unbounded
  attack surface.
- Version-string compatibility checks: rejected in favour of capabilities.
- Provider-specific fields in public contracts: rejected, blocks replacement.
